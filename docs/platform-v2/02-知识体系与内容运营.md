# 知识体系与内容运营

## 1. 分类方法：按目标组织，按能力检索

使用「领域 → 任务 → 工作流 → 步骤」组织执行路线；工具、模型、知识和案例是可复用对象，以关系关联，不复制成多份文章。

例如：游戏 → 3D 道具 → 图片到可导入引擎的道具 → 生成网格 → 修整 → UV / PBR → 导出验证。Meshy 或 Tripo 是生成阶段候选，Blender 是人工处理阶段工具；工作流选用关系是编辑判断，不等同于工具之间存在官方集成。

多维标签：输入素材、输出产物、2D/3D/音频/视频、经验、操作系统、目标引擎、语言、交互方式、运行位置、费用单位。技能难度基于路线的人工操作要求；工具热门程度不作为技能标签。

## 2. 首期任务地图：24 个任务

### 游戏开发

1. 玩法研究与一页设计说明。
2. 2D 核心玩法原型。
3. 角色与环境概念图。
4. 精灵图与循环动画。
5. UI、图标与道具套图。
6. 3D 场景道具与导入。
7. 音效、对白与文本本地化。
8. 宣传素材、试玩反馈与迭代。

### 3D 创作

1. 文本或单图生成概念网格。
2. 多视图参考准备。
3. 网格清理与重拓扑。
4. UV 展开与纹理烘焙。
5. PBR 材质与风格统一。
6. 骨骼绑定、权重与动画检查。
7. LOD、碰撞体与引擎导入。
8. 展示渲染和可打印模型检查（打印路线在第二阶段深入）。

### 视频创作

1. 选题、脚本与分镜。
2. 角色或产品参考图。
3. 图生视频与文生视频。
4. 跨镜头一致性与镜头衔接。
5. 配音、声音与背景音。
6. 剪辑、字幕和画面节奏。
7. 清晰度、帧率与交付检查。
8. 游戏预告、产品短片与竖屏社交内容。

其他领域保留扩展标签，不发布空分类页：编程、平面设计、写作、办公、研究、自动化。每个领域达到最低内容门槛后开放导航。

## 3. 内容对象与模板

**工具档案**：名称与别名、官网、开发者、工具类型、适用/不适用任务、功能证据、输入输出、版本、导出格式、学习成本、平台/语言、费用入口、相关模型、相关路线、来源与更新时间。

**模型档案**：基础模型与版本、厂商、模态、访问渠道、已核验能力、上下文或输入限制、输出规格、计费与模式、生命周期。不同能力字段分组，例如视频有时长/音频/分辨率，3D 有纹理/格式/拓扑；空缺不填零。

**工作流模板**：作品目标 → 适合谁 → 前置技能/素材 → 完成标准 → 分步执行 → 每步输入/输出 → 参数与提示模板 → 失败现象/排查 → 人工工作 → 替代工具 → 预算 → 来源/版本 → 关联知识。

**知识模板**：一句话解释 → 何时需要 → 小例子 → 怎么操作 → 常见误解 → 下一步路线 → 来源。术语文章避免百科式堆字。

**评测模板**：明确任务、样本与合法素材、产品/模型/日期/套餐、输入、参数、次数、成功判据、原始产物、裁判口径、时间与金额、失败记录、结论适用范围。不同测试条件不合并成排行榜。

## 4. 三条示范路线

以下是首发编辑方案，未实际跑通，不标记为实测教程。工具能力查证记录见来源文档；版本、套餐和资产权限须在正式测试时核验。

### A. 2D 俯视角游戏原型

目标：一个房间、一个角色、移动与碰撞、收集物和重开逻辑，可以运行并检查完成状态。示例规模是任务约束，不承诺固定工时。

- **输入**：一句话玩法、目标设备、选择的引擎、已有美术或风格参考。
- **步骤 1 约束玩法**：写一页设计说明和明确验收项；通用语言模型可辅助整理，人工删除不属于最小原型的系统。产物：设计说明。
- **步骤 2 做可运行灰盒**：在 Godot 或 Unity 中用基础几何与占位资源完成移动、碰撞和胜负条件。代码助手是候选类别，具体版本需另测。产物：可运行工程。先确认逻辑再制作美术。
- **步骤 3 统一视觉**：制作风格参考与资产清单；Scenario 作为资产制作候选，Ludo 作为策划/素材辅助候选。逐项检查透视、尺寸、透明边缘和动画帧规格。产物：整理好的 PNG / sprite sheet。
- **步骤 4 导入和校正**：按目标引擎设置切片、像素过滤、碰撞与动画速度。失败排查：接缝、抖动、裁切、透视不一致。产物：替换占位素材后的工程。
- **步骤 5 音效与测试**：音效候选可包含 ElevenLabs；检查循环、峰值、触发次数和授权记录。记录 5 次试玩的卡点，修复至少一个阻断。
- **交付**：工程与运行包、资产清单、已知问题、素材与工具版本。通过条件由运行结果判定，不以截图代替。
- **成本输入**：代码请求、图像生成与重试、音效条数、已购订阅、人工小时。人工时间单列。
- **替代路径**：预算紧时先使用自制几何/已授权现有素材；不会绘图不必先完成最终美术。
- **关联知识**：token 与上下文、占位资源、精灵图、帧动画、风格参考、资源导入。

### B. 单图到游戏用 3D 静态道具

目标：将一张椅子参考图制作成可导入指定引擎的静态道具。输入图需有使用权限；单图遮挡部分需要人为判断。

- **步骤 1 设定规格**：确认真实尺寸、目标平台、坐标/单位、面数预算、纹理规格与引擎。面数预算按项目设定，不写成所有游戏通用常数。
- **步骤 2 生成候选**：Meshy 与 Tripo 是图转 3D 候选。固定参考图记录尝试次数；先检查轮廓与结构，不用高分辨率贴图掩盖几何问题。
- **步骤 3 人工修整**：在 Blender 检查破洞、非流形、法线、薄片、隐藏面和模型比例；需要时重拓扑与 UV。产物：清理后的网格。
- **步骤 4 材质与导出**：检查 UV、颜色/法线/粗糙度等贴图和目标渲染方式；导出由工具与引擎共同支持的格式。格式可导出不等于贴图/骨骼必然无损兼容。
- **步骤 5 引擎验收**：导入、配置材质和碰撞，检查比例、坐标、阴影、性能与贴图路径；在目标平台实际运行。
- **交付**：网格、贴图、源工程、预览、导入说明与授权记录。通过条件：结构可用、材质正确、引擎运行无阻断。
- **失败路线**：腿部融合/椅背破损 → 先修几何或换参考；纹理糊 → 检查 UV 与贴图；动画对象另开绑定路线，静态椅子不要求骨骼。
- **成本输入**：生成、细化、纹理、导出所需套餐、失败次数、人工修整。自动绑定候选能力不构成“无需人工”的承诺。
- **关联知识**：拓扑、UV、PBR、法线、LOD、碰撞与坐标系。

### C. 30 秒竖屏产品短片

目标：用已有产品图片完成 30 秒短片。示例项目自定 1080×1920 / 30fps 为最终剪辑导出规格，不表示所有生成模型原生支持。

- **步骤 1 拆脚本**：确定受众、卖点与结尾动作；用 6 个约 5 秒镜头作为预算规划。实际生成时长按模型限制取整并裁切。
- **步骤 2 准备参考**：明确产品外形、包装文字、颜色和光照；重要文字后期叠加，避免依赖模型逐帧生成准确字样。
- **步骤 3 试一个关键镜头**：从即梦或 Runway 等候选中选一条路径。两者都提供视频生成入口，但可用型号、参数、地区和额度需单独核验。
- **步骤 4 批量扩展镜头**：固定参考图、逐镜头记录提示和参数，检查主体形变、运镜、运动连续性；只对不合格镜头重试。
- **步骤 5 配音与剪辑**：选择已有剪辑工具，统一画幅、帧率、色彩与节奏；声音可使用有授权素材或生成候选。检查音乐和口播的相对响度。
- **步骤 6 交付检查**：检查产品外形、文字、字幕安全区、音画同步、黑帧和输出文件；查看手机实际播放效果。
- **交付**：视频、剪辑工程、镜头清单、字幕、素材来源记录。
- **成本输入**：每镜头时长、每镜头尝试次数、每次或每秒额度、放大与配音、订阅余量。成功片长和付费生成片长分开展示。
- **替代路径**：预算不足时用静态产品图、手动镜头运动与剪辑完成部分镜头，减少必须生成的片段。
- **关联知识**：分镜、图生视频、参考一致性、帧率、字幕、重试成本。

## 5. 首发内容计划

目标库存属于待制作内容，不是现成资产：

- 3 个场景、24 个任务。
- 24 个深度工具档案（游戏 8 / 3D 8 / 视频 8 为编辑配额；跨领域工具去重，最终补足 24 个唯一档案）。
- 12 条端到端路线，每领域 4 条；上面三条先制作。
- 36 篇知识点，每领域 10 篇，另加 6 篇通用知识。
- 9 个小范围实测，每领域 3 个，报告实际样本量；先测任务能否完成，再比较体验。
- 原有 313 个模型条目作为待迁移目录基线，补充多模态清单与厂商差异报告；不能宣称已全部实测。

知识标题示例：为什么生成次数比提示词长度更影响视频预算；token 与订阅次数有什么区别；模型、平台和 API 渠道如何区分；为什么看起来漂亮的 3D 模型导入后有问题；什么时候需要 UV；为什么角色跨镜头会变脸；为什么代码能运行不代表玩法完成。

## 6. 编辑与更新机制

流程：发现 → 建草稿 → 提取逐条结论 → 关联官方来源 → 实际测试（必要时）→ 审核 → 发布版本 → 定期复核 → 变更/撤回。

角色：维护者可编辑和发布；未来多人团队区分投稿者、编辑、审核者、管理员。单人阶段允许同人审核，但记录角色与时间，禁止制造“独立审核”标签。

每条事实有 subject、字段、值、来源、观察时间、适用版本/套餐/地区、证据类型和状态。官方描述是「官方说明已查证」；实测只用于已经跑过的样本；用户报告未经复核不替换事实。

复核策略（运营计划，尚未启动）：价格/配额/可用性 7 天，能力与格式 30 天，基础知识 90 天；到期显示待复核。价格超过 30 天退出确定性费用比较；商用条款过期或冲突退出商用确定性筛选。新发布线索进入工作队列，目标 2 个工作日内完成分流，完整评测可更久。

自动抓取仅提出差异和草稿；人工确认后发布。优先官方结构化 API，遵守来源访问规则；引用使用必要摘要与链接，不复制整篇教程或未经授权的演示作品。

处理下架：保留历史详情与版本日期，禁止推荐为当前可用，指向已经审核的替代路线；字段冲突保留两份证据并显示待判定。

## 7. 推荐与评测纪律

- 官方能力、编辑适配判断、实测结果、赞助展示分开。
- “国内可用”拆成界面语言、注册、付款、访问区域和测试地点/日期；访问外部官网成功不能证明国内用户可用。
- 商用相关信息以具体套餐条款与素材条件记录，不给平台级永久「可商用」绿勾。
- 无实测可给“待验证候选”，不能写“最高质量”“一次生成可用”。
- 公开范围与缺口：目录覆盖、字段查证、案例实测三个完成度分别统计。
