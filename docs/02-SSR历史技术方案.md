# AI 知识站｜统一技术方案

版本：v3.0 · 2026-09-17。对应 [统一需求](01-需求文档.md) 与 [总清单](../TODO.md)。本文件是全站技术主文档；知识、模型、应用教程与计算器共用同一应用和数据体系。

## 0. 统一模块与路由

- `/`：综合 AI 知识站首页，主搜索与六栏目入口。
- `/learn`、`/learn/[slug]`：入门、概念、方法知识。
- `/models`、`/models/[slug]`、`/tools`、`/tools/[slug]`：模型/版本/平台/渠道。
- `/scenarios`、`/scenarios/[slug]`、`/tasks/[slug]`：多领域应用任务；游戏/3D/视频为首批深度内容。
- `/tutorials`、`/tutorials/[slug]`、`/workflows/[slug]`：单项教程与端到端路线。
- `/calculators/tokens`、`/calculators/video`、`/calculators/assets`、`/compare`：实用工具。
- `/updates`、`/benchmarks/[slug]`：重要更新、案例与评测。
- `/search`、`/saved`、`/methodology`、`/privacy`、`/admin`：共用搜索、收藏、来源方法和后台。

六栏目只是导航视图，共用 Layout / Search / Entity / Source / Revision。tutorials、workflow、article 通过内容类型与关系管理，不复制多个内容系统。

现有代码复用：`components/Calculator.tsx`、`workers/tokenizer.worker.ts`、`lib/engine.ts`、`lib/catalog.ts`、`data/tokenizers.json`、SSR模型页面与部署脚本。迁移先保持现有计数和费用行为，再将 UI 放到统一导航下。

保留原计算器1 MiB、本地正文、参考编码和费用情景边界。代码改造前运行已有基线；编码映射、真实预测和厂商全量审核仍是待办，不因整站合并而消失。

## 1. 架构决策

继续使用现有 **Next.js App Router + React + TypeScript**；公共页面坚持 SSR，计算器的敏感文本继续在浏览器 Worker 中处理。引入 PostgreSQL 保存结构化内容与关系，新增基于 Payload 的编辑后台。采用模块化单体，先部署单个 ECS 应用实例，不在首发引入微服务或图数据库。

选型理由：Next.js 延续已有代码与 SSR；Payload 提供基于 Next.js 的后台基础、结构化内容和访问控制。备选为独立 Directus 后台（需额外服务和适配）或全自研后台（开发与维护工作更多）。选择 Payload 是设计决策，**其与项目当前 Next.js 16.3.5 / React 19.3.0 的具体兼容性尚未验证**，需先做依赖安装、构建、认证与版本草稿 POC，再锁定版本。不能以官网“支持 Next.js”代替当前组合兼容验证。

如果 POC 不通过，先评估兼容的依赖组合和回归成本；无法合理兼容时将 CMS 独立部署，不为接入后台破坏已验证的计算器。

依据：[Next.js 自托管](https://nextjs.org/docs/app/guides/self-hosting)、[Payload 安装](https://payloadcms.com/docs/getting-started/installation)、[Payload 部署](https://payloadcms.com/docs/production/deployment)。

## 2. 服务边界

浏览器 → Nginx / HTTPS → Next.js SSR / Route Handlers → 内容服务 → PostgreSQL。

- 浏览器：本地 token 计算、费用情景、公开筛选、匿名进度、导出。
- Next.js：公共页面、查询接口、审核发布与后台会话；页面直接调用内容服务，不绕一圈请求自身 HTTP API。
- PostgreSQL：实体、事实来源、版本、路线步骤、审核、任务队列、公开搜索投影。
- OSS：有授权的截图、案例产物与备份；应用服务器用 RAM 最小权限访问，不将密钥发给浏览器。图片公开资源和私有审核附件分桶或分前缀策略。
- 后台 worker：定期复核提示、链接状态检测、差异采集、搜索索引刷新；与 web 分进程运行，避免长任务占用 HTTP 请求。
- 首发无需用户素材上传、生成 GPU、付费模型 API 或向量数据库。

SSR 数据缓存只缓存公开内容对象。保留当前按请求生成 CSP nonce 的机制：**不能将含 nonce 的完整 HTML 在 CDN / Nginx 上跨请求共享**。静态哈希资源可长期缓存，公开内容服务可短缓存；后台和用户私有响应 `no-store`。多实例阶段再验证共享缓存和失效协调，不直接复制单实例本地缓存假设。

## 3. 数据结构

### 身份、目录与能力

- `providers`：厂商 ID、名称、官网、别名。
- `tools`：平台/桌面软件/引擎/编程助手等类型；工具 ID、slug、厂商、描述、运行位置、发布状态。
- `models`：基础模型 ID、厂商、名称、模态；与现有 canonicalId 对应。
- `model_versions`：模型版本、有效时间、别名、生命周期；版本变更不覆盖旧评测。
- `offerings`：具体工具或 API 渠道提供的模型/功能、访问方式、地区、套餐、供应商 ID。一个模型可对应多个 offering，一个平台也可包含未公开底层模型的功能。
- `capabilities` / `entity_capabilities`：输入输出、格式、模式、约束；带证据和适用范围。不同模态采用判别联合 schema，避免全靠无约束 JSON。
- `tasks`：领域、目标、输入、输出、前置技能、目标规格。
- `task_tool_links`：工具在任务中的角色、适配理由、证据状态；可表达配套非 AI 工具。

### 费用、知识与工作流

- `price_rules`：offering、币种、计费单位、数值、阶梯、时段、套餐/版本、生效/核验时间、来源、规则版本；未知值为 null。
- `plans`：订阅周期、购买额、包含额度、额度类型、结转/过期与超额规则；不同平台 credits 使用独立单位 ID。
- `workflows` / `workflow_versions`：任务、适用条件、完成标准、证据级别。
- `workflow_steps` / `step_dependencies`：次序、依赖、输入输出契约、操作内容、工具候选、通过条件、常见错误；发布前校验无环。
- `articles` / `article_versions`：知识正文、前置知识、相关任务。使用受限富文本 AST；投稿内容不得作为任意 MDX/JS 执行。
- `benchmarks` / `runs`：样本、模型/工具版本、参数、输出引用、重试、耗时、实际计费、结论；作品文件须有权存储与展示。

### 信任与运营

- `sources`：规范化 URL、出版方、抓取/观察时间、内容摘要 hash、访问状态。
- `claims`：entity_type/entity_id、field、value、source_id、scope、observed_at、valid_until、evidence_type、review_status。
- `revisions` / `audit_logs`：谁、何时、改动、审核和发布动作。
- `coverage_entries`：厂商/领域、待查型号、纳入/排除理由、缺失字段；统计口径与目录分离。
- `search_documents`：只包含已发布内容的可再生检索投影。
- `corrections` / `jobs`：纠错、复核任务与幂等键。
- `collections` / `progress`：第二阶段登录同步表；首发只存本机版本化 JSON。

slug 变更写入 redirects，唯一 ID 不变。关键关系使用外键；删除有引用对象须先归档或迁移关系。发布日期不能取抓取日期代替；verified、reviewed、published 分别记录。

## 4. 选型引擎

首发是透明规则引擎，不在每次用户访问时调用大模型。

输入结构：taskId、输入素材类型、技能、目标格式/软件、运行平台、预算币种/上限（可选）、访问偏好、商用要求、已有订阅。项目自由文本默认本地匹配任务，不写服务器日志。

处理：

1. 找到已发布的任务路线与候选工具，不对全部模型盲目打分。
2. 验证硬条件：输入/输出、工具依赖、目标系统、明确预算上限、必要访问与条款条件。
3. 硬条件 `unknown` 分到待确认组；`false` 显示排除原因；只有满足已知硬条件的进入可执行候选组。
4. 按用户策略作确定性排序：省预算优先完整且新鲜的增量费用；易上手优先较少人工步骤/先备技能；可控优先有对应控制能力证据的路线。
5. 相同条件下用证据完整度和稳定 ID 打破平局。无统一质量样本时不跨工具输出“综合性能分”。

输出含候选、备选、理由、排除项、未知项、规则版本和依据 ID。预算不完整不能自动成为最低价首选。编辑关联只是候选来源，不提升为实测质量标签。

P1 可加入有引用的检索问答：仅检索已发布知识片段，返回来源和日期；内容不足时明确无法确认；先评测回答正确率/引用覆盖率，再启用付费调用。抓取内容永远作为数据，不能执行其中的指令。

## 5. 成本引擎扩展

保留 Decimal，按模型提供 adapter，不把所有模态折成 token：

- 文本：复用现有输入/缓存/输出/推理费用与参考编码标签。
- 图像：数量 × 每项尝试 × 规格对应每次费用；编辑、放大和导出另列。
- 视频：逐镜头计算。若按秒计费，使用实际计费时长（按服务商规定取整），乘尝试次数与分辨率/模式单价；按次计费则不能使用每秒公式。
- 3D：生成、细化、纹理、绑定、导出各阶段分别求和；不是所有功能都会另计费，必须按 offering 规则。

设 `u_i` 为每次计费数量，`a_i` 为尝试次数，`p_i` 为单价，则用量费用 `Σ(u_i × a_i × p_i)`。如果某一步单价未知，结果是已知部分合计与待确认项，不输出完整总价。

订阅必须展示三种不同指标：

1. **新现金支出**：为了当前项目必须新增购买的套餐/额度/超额费用。
2. **额度使用量**：本项目消耗几种平台额度，各自显示，不能将不同 credits 相加。
3. **分摊成本情景**：用户选择如何分摊既有订阅，属于规划假设，不冒充实际新增付款。

已有订阅可以使本项目新增支出为零，但不表示额度没有成本。套餐购买带离散门槛，不以平均每 credit 价格代替真正付款额。套餐梯度未知时只显示用量与官方价格入口。

项目工作流共享同一个套餐时，用 offering/plan/计费周期键去重；不能每一步重复计入完整订阅。金额统一币种需要注明汇率来源和时间；人工工时与服务费单列。预算情景的成功率不默认采用未经验证的模型值，用户可直接填尝试次数。

例：6 个 5 秒镜头，每镜头 3 次尝试，按秒收取的假设价格 ¥0.20/s，则生成 90 秒、费用 ¥18；这是演算示例。需要订阅购买额或其他服务时另外列明，不声称 ¥18 一定能买到服务。

## 6. 搜索与接口

先用 PostgreSQL 的别名表、前缀索引与 `pg_trgm` 检索已发布投影；中文短词结合标准化别名与受控关键词。不要默认英文全文分词即可满足中文。拼音别名需要来源或编辑维护，不自动制造实体名。

查询排序：任务/标题/别名精确匹配 → 前缀 → 关键词相似；结果按内容类型分组。评测集至少 60 条中文/英文/别名/错别字/短词查询，关注目标页面 Top 3 命中；不足再引入独立搜索服务，避免过早增加 ECS 负担。

API 设计：

- `GET /api/v2/search?q=&type=&cursor=`：公开检索，限制 q 长度与页大小，不返回草稿。
- `GET /api/v2/tools`、`/tasks`、`/workflows` 与各自 `[id]`：版本化公开数据。
- `GET /api/v2/rules?taskId=`：返回公开任务规则包，让私人约束在本地运行。
- `GET /api/v2/prices?offeringIds=`：公开报价快照，带时间、版本、来源。
- `POST /api/v2/corrections`：用户主动提交，限流、字段校验和防垃圾。
- 后台写入走 CMS 认证权限，发布操作需事务和版本检查；不要给公共 API 默认写权限。

响应统一 `{data, meta:{version, checkedAt}, nextCursor}`；错误 `{error:{code,message,requestId}}`。查询失败 400/404/429/503 有明确语义。旧 `/api/v1/catalog` 保持兼容，变更提前记录。

## 7. CMS、任务与安全

发布事务：校验 schema → 校验来源/实体关系/步骤依赖 → 写不可变 revision → 更新 published 指针 → 提交后发出失效/索引 job。索引延迟时页面依然只读已发布版本；失败可重试。并发更新以 revision 乐观锁防覆盖。

后台会话使用服务端验证、HttpOnly/Secure cookie、CSRF 防护及角色权限；URL 隐藏不能代替认证。未来加入 MFA 需完成端到端验收。密钥不进入内容表或公开 JSON。

采集 worker 只访问审核过的域名，阻止内网/云元数据 IP、限制重定向/体积/超时，避免用户纠错 URL 触发任意 SSRF。下载媒体需检查 MIME、尺寸并处理风险格式；首发不接用户上传的可执行文件。

CSP 保留 nonce。加入 OSS 图像域名需明确白名单；知识正文外链不需要放开 `connect-src *`。未启用的第三方统计、支付和模型请求不预先添加。

应用日志记录 requestId、状态和耗时，屏蔽查询内容、正文、凭证与上传 URL token；纠错文本和联系方式设保留期限（拟 90 天，需运营确认），用户可请求删除。单机备份应加密并隔离访问权限。

## 8. ECS 部署与运维

先确认实际 ECS CPU/内存、磁盘、架构、系统与已有服务。容量规划起点建议 4 vCPU / 8GB RAM、适当磁盘，用压测验证；这不是当前 ECS 配置，也不是报价。预算或规格较小时先缩减后台并发，构建放在外部环境。

首发方案：Nginx + Next.js web + 单 worker + PostgreSQL 同机（开发/小流量试运行）；OSS 存媒体。数据库不映射公网端口。单机故障影响所有服务，应在流量或可靠性要求提高时迁移托管数据库和独立 worker。

每日备份数据库到隔离存储，部署前额外备份；目标 RPO 24h、RTO 4h，仅在恢复演练通过后承诺。发布使用版本镜像；数据库迁移采用先扩展后清理，旧应用不兼容的破坏性迁移不能只靠回滚镜像恢复。

健康检查区分 live 与 ready，后者检查数据库及必要内容版本。监控错误率、P95 响应、内存/磁盘、任务积压、备份年龄和复核队列；告警由运营接收，不能只记录日志。

## 9. 在同一项目中合并迁移

1. 保留现有计算器验收基线；先做 CMS 兼容 POC，不替换主应用。
2. 建 entities/revisions/sources/coverage schema 与可回滚迁移脚本。
3. 把 `data/catalog.json` 导入为暂存数据；313 条是导入时快照数量，保持 ID、canonicalId、报价渠道和参考编码标签。幂等导入、数量核对、价格单位对照、旧 API 回归。
4. 创建场景、工具、工作流与知识数据；`tool` 不从模型名机械生成。新模型证据与旧目录分开补审。
5. 将旧计算器组件挂到 `/calculators/tokens`；原首页切换为平台首页，旧收藏首页用户仍能在首屏找到入口。保留旧模型路由。
6. 页面数据先通过 repository 接口访问：开发可读快照，上线读数据库；迁移期间以选定的数据源为唯一写源，禁止同时写 JSON 和数据库。
7. 小流量验证后切首页；新模块使用 feature flags。平台模块异常时保留计算器与旧目录服务。
8. 若暂不能完成 CMS 数据审核，可上线少量已审核路线；不发布空专题、演示评分或草稿教程。

## 10. 验收与性能

- 单元：费用单位/套餐去重/阶梯/时长取整/未知单价、关系与无环检查、规则确定性和未知硬条件。
- 集成：事务发布、撤回、权限、过期来源、搜索去草稿、重复导入、旧 ID/API 兼容、失败 job 重试。
- E2E：三个完整任务路径、筛选/比较、进度恢复/版本变更、预算/导出、匿名使用、编辑发布撤回。
- 安全：草稿泄漏、跨角色写入、XSS、CSRF、SSRF、日志与网络正文检查。
- 可访问：375/768/1440px、键盘/焦点、读屏关键流程、图像说明与 contrast。
- 目标预算：指定 ECS 环境下 20 并发知识页请求 P95 < 1s；搜索 P95 < 500ms；手机模拟网络 LCP < 2.5s、CLS < 0.1；这是验收目标，部署前需测量并记录条件。
- 回归：原 33 单测/8 E2E 作为已有基线，新增模块需新增用例；不能用旧通过数表示新平台已验收。


## 11. 全站验收对应

K01/K02/K04/K05/K10：统一导航、知识/场景/教程/更新内容类型、搜索与关系。K03/K11：模型、渠道、来源、覆盖和后台。K06/K07/K08/K09：保留原本地工具并扩展费用适配器。K12/K13/K14/K15：SSR、兼容、部署和最小化反馈。

设计阶段不会安装数据库或 CMS，也不修改现有生产代码。本方案中的未验证依赖组合和 ECS 容量必须通过 POC 与实机测试。
