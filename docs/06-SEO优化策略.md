# ruming.top SEO 优化策略与执行清单

2026-09-17。基于当前 React SPA + Node.js API 项目源码审查。本文是执行方案，未修改运行时代码，未接入搜索平台账户，未验证正式域名实际收录、流量或排名。关键词为内容候选，不是经过搜索量工具验证的数据。

## 一、目标与定位

站点定位：帮助中文独立创作者理解 AI、选择工具、完成游戏/3D/视频作品。资讯负责发现新变化，教程负责解决问题，计算器负责促成实际使用。

初期优先争取明确任务的长尾搜索，不把“AI”“人工智能”等宽泛词作为短期排名目标。建议内容投入：60% 原创任务教程，25% 工具与费用说明，15% 资讯解读；这是编辑资源建议，不是排名公式。

主要转化为：打开并完成一次工具计算、从文章进入相关工具、主动收藏教程。点击外部资讯原文是资讯模块的有效使用，但单独统计，不能与站内工具转化混为一谈。

中文内容优先考虑百度、Bing 与 Google；各搜索平台的抓取及渲染结果分别实测，不假定 Google 的 JavaScript 能力适用于所有爬虫。[百度搜索资源平台](https://zy.baidu.com/)、[Bing Webmaster Tools](https://www.bing.com/webmasters/about)。

## 二、当前源码发现：先解决可抓取与可索引

### P0：公开内容接口被 robots 阻挡

证据：`backend/src/server.ts` 输出 `Disallow: /api/`；`frontend/src/content.tsx` 首屏依赖 `/api/v1/bootstrap`，资讯依赖 `/api/v1/news`。这是渲染所需资源被屏蔽的风险，不能靠提交 sitemap 弥补。

行动：明确允许渲染所需的公开 GET 接口；保留对管理/私人接口的访问控制。公开 JSON 可用 `X-Robots-Tag: noindex` 避免作为独立搜索结果，页面仍可请求。robots 不是鉴权机制，不用于保护秘密。

验收：在线 URL 检查工具渲染后的 HTML 能看到首页正文、文章正文和资讯标题；没有关键资源 blocked。Google 对 JS 页面有抓取、渲染、索引三个阶段，允许脚本并不等于所有依赖请求都可用。[JavaScript SEO 官方说明](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。

### P0：各路由元信息没有完整接管

证据：`frontend/index.html` 只有全站通用标题与 description；`main.tsx` 读取 H1 更新 title，未按路由更新 description、robots、Open Graph。页面遗留的 `export const metadata` 在当前 Vite 路由中没有被读取。

行动：建立单一 SEO 配置/解析层，按路由与实体输出 title、description、canonical、robots、分享信息。删除或接入失效的 metadata，避免两套声明。H1 可以保留品牌表达，搜索标题应说明用途。

标题示例（需与实际内容一致）：

- 首页：AI 知识站｜AI 工具、创作教程与词元计算器。
- `/news`：AI 资讯｜大模型、应用与硬件动态 - AI 知识站。
- `/calculators/tokens`：Token 计算器｜词元计数与模型费用估算 - AI 知识站。
- `/learn/image-to-3d`：图片转 3D 工作流：生成、检查与导入 - AI 知识站。
- `/tools/meshy`：Meshy 工具介绍｜能力、使用限制与官方入口。

description 用一两句话解释页面能解决什么问题和适用边界，不堆砌关键词；不是固定字符数越接近上限越好。词元工具必须保留“参考编码”和“费用估算”限定，不能宣传精确预测所有模型用量。

### P0：分页 canonical 与链接发现

证据：`main.tsx` canonical 仅使用 pathname，导致 `/models?page=2` 与 `/news?page=2` 指向第一页；资讯分页使用按钮，后续页缺少可爬的 href。

行动：可索引分页保留 `?page=2` 并指向自身，第一页统一省略 `page=1`；分页使用真实 `<a href>`，React 可增强交互。搜索、任意筛选组合与正常分页分开处理，不把明显不同的内容强行标为第一页的重复版本。Google 明确建议分页使用自身 canonical。[分页官方说明](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)。

### P0：无效路由的 HTTP 状态

证据：Nginx `try_files ... /index.html` 为任意不存在的路径返回 200；前端 NotFound 仅显示提示，没有 noindex。

行动：生成合法路由清单并让静态服务按清单匹配；不存在的路径/实体返回真正的 404。客户端错误页加 noindex 作为补充；有效页面不能共用包含 noindex 的入口。过期文章有真正替代页才 301，无替代内容用 404/410，不全部跳首页。

验收：正常页面 200，虚构路径及实体 404，永久迁移单跳 301，API 故障与“内容不存在”分开处理。

## 三、保持前后端分离的渲染策略

### 当前路线：继续纯 SPA

先完成上述基础修复，让支持 JavaScript 的搜索引擎能够获取和理解内容。缺点是首屏依赖 JS、API 与渲染队列；部分爬虫及社交分享抓取器可能拿不到正文或独立元信息。不能承诺做几个 meta 标签即可消除这些限制。[Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。

### 可选增强：发布时生成静态 HTML（SSG）

如果自然搜索成为主要增长渠道，建议给首页、知识文章、场景、工具详情及精选模型详情加入发布时静态生成。HTML 由 Nginx 直接提供；交互仍由 React 接管；Node.js 继续负责内容 API 和采集，不恢复请求时 SSR。

SSG 也是一种预渲染，会改变当前“仅客户端渲染”的交付方式，应作为后续明确的架构选择，不能在本次策略中宣称已完成。所有访客与爬虫返回同一份内容，不使用按 User-Agent 单独提供关键词页面的做法。

更新机制：编辑发布触发生成；资讯聚合可按采集完成事件合并触发静态快照，并与动态 API 使用同一数据源。生成失败保留上一版，成功原子发布；时间显示真实更新时间。交互计算器无需生成私人输入结果，静态输出工具介绍、用法、限制与相关指南即可。

若坚持完全不预渲染，继续 SPA 优化并通过各平台渲染结果评估，接受收录可见性上限。

## 四、哪些页面应参与搜索

优先收录：完整首页、原创知识与教程、场景专题、有充分资料和独立说明的工具/模型详情、工具使用说明与真实资讯栏目。

不主动索引：站内搜索 `/search`、收藏 `/saved`、临时工具比较组合、任意关键词/排序/筛选参数页、空页面。采用 noindex 并允许爬虫读取该指令，不一边用 robots 阻挡页面、一边期待爬虫读取页面里的 noindex。

模型目录不以“全部条目进入索引”为目标。当前模型多为渠道字段快照，应逐步补充适用任务、来源、计费渠道、已知限制与有依据的比较。资料不足的条目可保留给用户查阅，达到内容标准后再加入可索引集合与 sitemap。

sitemap 仅列希望索引的规范 URL、正常返回的实体。lastmod 使用实际内容变化时间，不能每次请求都改成当前时间。暂不需要为了数百条 URL 复杂拆分；内容增长后再按知识、工具、模型拆分。canonical 是规范化信号，不是强制保证。[规范 URL 官方说明](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)。

## 五、资讯 SEO：从“标题列表”建立有用的内容入口

当前 `/news` 只有标题、分类、来源、配图和外链，没有本站新闻正文详情。因此先将其作为资讯导航维护；不为每一条 RSS 自动生成同质的详情页，也不把来源报道标成本站原创 NewsArticle。

建议新增编辑型解读内容，但仅在有人整理和核验后发布：

1. 这次发生了什么：简洁转述，链接第一手公告，分别记录发布时间与核验时间。
2. 与创作者有什么关系：例如对游戏原型、3D 资产处理、视频制作的具体影响。
3. 哪些能力已确认，哪些仍缺价格/地区/许可资料；不编造实测结论。
4. 下一步怎么做：链接相关教程、工具档案或计算器。

先按每周 1 篇高价值解读试行，不要求每天为发布而发布。对真实事件的独立分析可使用本站永久 URL；普通聚合条目继续直达原文。避免仅翻译或替换措辞后批量建页。Google 的规模化内容滥用政策关注以操纵排名为目的、缺少用户价值的内容，是否使用 AI 不是唯一判断标准。[搜索垃圾内容政策](https://developers.google.com/search/docs/essentials/spam-policies)。

图片使用来源公开图片时核对使用条件；外链图片不等于已取得再分发许可。图像表达独立信息时写准确 alt，同一链接内仅重复标题或分类的装饰图可保留空 alt，不能为了 SEO 堆关键词。

## 六、关键词与首批内容计划

以下为待验证的中文搜索意图，不声称有已知搜索量或低竞争。优先完善现有 URL，避免新建相同意图的重复文章。

第一组：可计算的问题。

- Token 是什么、中文如何计算 token → `/learn/tokens` + 计算器。
- 推理 token 与输出 token 如何计费 → 扩充推理预算文章，链接费用计算。
- AI 视频预算怎么算、生成失败重试怎么计费 → 素材预算说明与工具。

第二组：独立创作者任务。

- 图片转 3D 后如何检查模型、导入游戏引擎 → 扩充现有 3D 工作流，提供真实截图及检查清单。
- 用 AI 做游戏原型需要哪些工具 → 游戏场景与原型教程，区分代码、美术、音频环节。
- AI 视频从脚本到成片怎么做 → 现有视频工作流，明确素材一致性与人工剪辑步骤。

第三组：具体工具与选择。

- Meshy 和 Tripo 如何按资产需求选择 → 编辑型比较文章，不能冒充未进行的质量实测。
- ComfyUI 适合什么任务、如何组织工作流 → 工具档案与教程。
- 某模型 API 价格怎么计算 → 经核验的模型详情与费用工具，区分渠道价格和官网价格。

每篇围绕一个主要意图：直接回答 → 操作步骤/依据 → 常见限制 → 相关工具与下一步。现有通用文章不足时补实操截图与失败案例，不用统一字数指标填充。每周维护 2 篇教程/说明 + 1 篇资讯解读；个人时间不足时缩减频率，保持核验质量。

内链路径：场景专题 → 教程 → 工具详情/计算器 → 相关原理。链接使用描述性锚文本；重点页面从首页或一级栏目进入，避免只存在 sitemap 中。术语解释、教程和工具页面各自承担不同意图，减少自己与自己竞争。

## 七、结构化数据与性能

结构化数据仅描述页面真实可见信息：

- 原创知识/教程：Article 或 BlogPosting，真实作者、标题、发布日期、修改日期及合规配图；无编辑核验不得填虚构作者或发布时间。
- 内层页面：BreadcrumbList，对应真实层级。
- 资讯聚合页：CollectionPage/ItemList 可作语义描述，不承诺专属富结果；不得把整个外链列表伪装成一篇本站新闻。
- 计算器：按实际 WebApplication/SoftwareApplication 属性评估，缺失的评分/评价/价格不要伪造；先做好可见使用说明。

Google 支持 Article 标记帮助理解文章，但正确标记并不保证富结果或排名提升。[Article 官方说明](https://developers.google.com/search/docs/appearance/structured-data/article)。

性能优化先实测：首屏相关图片避免全部 lazy；下屏配图保持懒加载和尺寸占位；适当采用响应式图片、压缩及经许可的本地/CDN资源。拆分路由代码，避免看一篇文章也下载整个计算器逻辑；拆分 bootstrap，避免所有页面必须拉取全部模型数据。当前已有 Worker 与图像比例占位，保留。

上线后以真实用户第 75 百分位为目标：LCP≤2.5 秒、INP≤200 毫秒、CLS≤0.1；桌面和移动分别看。Lighthouse 实验室分数用于定位问题，不冒充真实用户指标，也不保证排名。[Core Web Vitals 官方说明](https://developers.google.com/search/docs/appearance/core-web-vitals)。

## 八、发布、推广与度量

部署先统一 `https://ruming.top` 为主域，HTTP/其他已配置主机名永久重定向；检查 TLS、压缩、缓存与移动端访问。开发/预览环境不参与索引，正式环境不能误带全站 noindex。

域名上线后验证 Google Search Console、百度搜索资源平台和 Bing Webmaster Tools；按平台实际开放能力提交 sitemap/URL，并抽查代表页面的渲染和索引状态。需要站点所有权/DNS 或文件验证，本次未执行账户操作。

获取自然引用的重点是可复用教程、计算方法、实测结果和检查清单。在相关社区分享能直接解决问题的内容，公开身份，遵守平台规则；不购买垃圾外链、不批量群发、不把推广数量当作链接质量。

每周记录：

- 技术：有效页面数、提交与已索引 URL、排除原因、抓取错误、关键资源阻挡、移动端性能。
- 搜索：按搜索引擎、页面组与查询查看曝光、点击、CTR，品牌词与非品牌词分开；平均位置只是参考。
- 产品：自然搜索进入后工具打开/计算完成/收藏事件；不采集提示词正文、私人报价、导入文件或完整搜索文本。
- 内容：发布与真实维护成本、获得非品牌曝光的文章、用户纠错及改进记录。

尚无线上基线，不承诺 30 天收录量或 90 天访问量。先建立前两周基线，再按页面类型定阶段目标；不要用 site: 搜索数量替代站长平台数据。
