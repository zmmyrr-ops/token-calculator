# AI 知识站｜统一需求文档

版本：v3.0 · 2026-09-17。本文是整个项目唯一的产品需求入口，合并原词元计算器与 AI 知识平台需求。

已确认：React / Next.js、React SPA（已替代旧 SSR）、阿里云 ECS、已有备案域名。当前已实现根路由知识站首页、统一导航/搜索、9篇知识与教程、计算器及模型目录；工具档案、场景、比较、素材预算和本机收藏/进度已实现；后台与运营功能继续按总清单开发。工作名称统一为「AI 知识站」，正式品牌待定。

关联：[统一技术方案](02-技术文档.md) · [总开发清单](../TODO.md) · [页面原型](platform-v2/prototype.html)。

## 1. 整站定位

一个帮助用户**了解 AI、选择 AI、学习使用 AI，并掌握使用成本**的综合知识站。

用户既可以问“token 是什么”，也可以查“这个模型有什么区别”“做游戏有哪些工具”“图片怎么变成 3D”“做视频用什么平台”。所有答案、工具和计算能力属于同一个网站，通过知识关系互相连接。

首页主张：**了解 AI，找到适合你的用法。**

核心价值：降低理解概念、比较产品、寻找教程和预算决策的成本。已完成的词元计算器是整站的实用工具模块；游戏、建模、视频是应用场景分类。独立创作者仍是首批重点服务用户，决定内容制作优先级，不限制整站定位与知识范围。

## 2. 用户与核心利益

- AI 新手：用能理解的语言建立概念，知道模型、平台、工具、API、订阅之间的关系。
- 日常使用者：按写作、学习、办公、设计等任务找到适合的工具与操作方法。
- 独立创作者：按游戏、3D、视频任务组合多个工具，理解中间文件、人工步骤与交付标准。
- 开发者：查看模型能力、API 渠道、上下文与计费，计算 token 和费用情景。

同一用户可在这些角色间切换，不要求注册或先选身份。基本资料、知识、来源和基础计算首期免费可用。

## 3. 统一信息架构：六个一级栏目

### 3.1 AI 知识

按概念和学习问题组织：AI 入门、大模型基础、提示词与上下文、推理模式、多模态、RAG / Agent、AI 创作基础、费用与使用边界。

文章包含一句话解释、何时用到、例子、操作或判断方法、误区、来源、更新记录与相关应用。入门路线从“模型与平台”到“怎么选工具”再到“完成一个任务”。不把全部文章堆成新闻流。

### 3.2 模型与平台

统一检索厂商、模型、模型版本、平台、软件工具和 API 渠道，但明确各自类型。

模型范围保留用户要求：现有市面上所有中高端模型作为持续覆盖目标；包括语言、代码、图像、视频、音频和 3D。基础目录广覆盖，详细测试分阶段进行；未核验字段留空并显示缺口，不能把全量收录等同于全量实测。

详情显示：适合什么、输入输出、能力与限制、模式、访问方式、运行环境、价格口径、来源与时间、相关知识和教程。平台可能含多个模型，同一模型可能有多个价格渠道。

### 3.3 应用场景

按“想做什么”组织，分类包括：游戏开发、3D 建模、视频创作、图像与设计、编程开发、写作与内容、办公与学习、音频与音乐、研究与自动化。

分类属于同一套可扩展体系。首批游戏/3D/视频做深入，其余分类达到有用内容门槛后逐步发布；空栏目不公开，首页不展示尚不存在的教程数量。

每个场景页有子任务、需要的知识、工具选择、教程和成本入口。例如“3D 建模”同时链接拓扑/UV 知识、Meshy 等候选平台、完整操作路线与费用工具。

### 3.4 教程与实践

同时支持单项操作教程、端到端工作流、问题排查、模板与有证据的案例。

教程必须写清：前置条件、使用版本、输入、步骤、输出、检查标准、常见失败、替代方法与费用假设。具体游戏/3D/视频完整示范继承 [内容设计中的三条路线](platform-v2/02-知识体系与内容运营.md)，发布前仍需实测。

### 3.5 实用工具

词元计算器、模型/推理预算比较、图像/视频/3D 费用情景、同类工具比较器。功能与知识相互链接：从 token 文章进入计算器，从计算器进入编码说明和模型详情。

未来可加入提示词结构检查、上下文容量规划等工具，以真实需求决定优先级。不能把固定规则建议描述为自动预测未来输出或保证最优模型。

### 3.6 更新与评测

展示会影响用户决策的重要变化、模型/平台版本记录、同口径实测和失效提醒。所有条目关联模型、知识或教程，不做与本站知识体系无关的热点堆砌。

官方说明、编辑判断、实际测试和用户反馈分开展示。没有实测不发布质量排名；赞助不改变自然排序。

## 4. 内容之间如何连接

核心实体：知识点、任务、工具/平台、模型/版本、供应渠道、教程/工作流、费用规则、评测、来源。

示例链路一：token 概念 → 本地计数 → 模型费用比较 → 模型详情 → 如何选择推理预算。

示例链路二：我想做游戏 → 制作角色素材 → 平台候选 → 精灵图知识 → 导入教程 → 素材费用。

示例链路三：我想做视频 → 脚本/分镜 → 视频模型与入口 → 角色一致性教程 → 重试预算 → 导出检查。

这些是同站内不同入口，不另建互相割裂的子站，不重复维护同一模型或报价。

## 5. 首页、搜索与统一体验

首页首先提供统一搜索：“搜索知识、模型、工具或你想完成的事”。下面依次为六栏目入口、入门知识、常见应用场景、精选教程、常用工具和重要更新。

游戏/3D/视频作为精选场景出现，不占用整站品牌与所有首屏叙事。桌面导航与移动菜单使用同一套栏目名称，所有页面继承统一布局、搜索、来源标记和收藏。

搜索按知识、模型/平台、场景、教程、工具分类显示。首期关键词和别名匹配，无法确定意图时让用户选择，不冒充通用智能问答。公开关键词可进入搜索 URL；私人提示词、项目描述和导入文件不进入 URL 或统计日志。

匿名可读可用；收藏、教程进度和基础偏好先本机保存，显示清除/导出与设备限制。账户同步放后续，不作为读知识的门槛。

## 6. 已有词元与选型需求完整纳入

- 纯文本与 TXT/MD 导入，UTF-8 校验、1 MiB 限制、字符与字节统计、清空撤销。
- 固定编码本地 Worker 计数、防抖、取消、竞态隔离；标明精确编码计数与模型参考计数的区别。
- 至少保留现有两份词表及版本/hash。每个型号的官方映射未核验时不得声称精确 API 账单计数。
- 回答长度与推理用量低/典型/高预算及自定义；未知推理消耗不能默认零。
- 输入/输出/缓存/请求及适用阶梯/时段费用，币种与手动换算、月用量、私人报价、容量与过期检查。
- 模型真实模式枚举逐条核验；不同强度不使用臆造 token 倍率。
- 按任务、成本与约束给可解释候选，证据不足时降级；质量建议不冒充实测排名。
- 目录搜索、分页与详情广覆盖；最多6个语言模型同时预算比较不限制目录收录量。
- JSON/CSV/复制导出带假设、来源和版本；默认排除原文，CSV 防公式注入。
- 正文默认本地处理；偏好不保存正文。未来云端分析单独说明发送内容与费用，需要主动启用。
- 实际输出/推理统计预测与自动路由保留后续方向：先取得 usage 样本、评估误差，再考虑集成。首期是知识和建议，不代用户调用其他平台。

原始细粒度边界见 [历史计算器需求](01-词元计算器历史需求.md)，与本文冲突时以本文为准；已有实现与限制见 [计算器验收](03-验收记录.md)。

## 7. 非 token 费用与场景选型

视频可能按秒/次/积分，图像按张/规格，3D 按生成/纹理/绑定等阶段，套餐又有额度与购买门槛。分开展示消耗量、新增现金支出、订阅分摊假设与人工时间；不同平台积分不能直接相加。

任务选型先收集目标、素材、经验和输出要求，再选填预算、访问环境与商用条件。未知硬条件进入待确认组，给最多3条有理由的路线。最多4项同类平台做横向比较；不同类别只能按步骤职责对照。

## 8. 内容质量与维护

所有重要能力、费用与使用条件关联来源、适用型号/版本/套餐/地区、观察时间和审核状态。官方有此功能不等于本站已测过质量。基础知识可长期复用，价格/可用性需要更短复核周期。

计划复核周期：价格/额度7天、功能30天、基础知识90天；超过时限标记待复核，超过30天未复核的价格退出确定性费用排名。公开覆盖与缺口，不承诺目前已经穷尽所有模型。

后台支持草稿、来源、编辑、预览、审核、发布、撤回、版本与纠错；抓取只生成待审核草稿。详细内容模板与示范为 [内容附件](platform-v2/02-知识体系与内容运营.md)，其创作场景属于全站内容子集。

## 10. 商业与迭代范围

免费层覆盖基础知识、档案、来源与常用工具。后续验证专题教程包、跨设备项目组织、版本提醒和团队知识空间的付费需求；联盟与赞助明确标注。定价仍是假设，不能写成已经售卖的权益。

首发必须具备整站骨架、基础 AI 知识、已有模型目录和计算器，并制作游戏/3D/视频的一批深度案例。原24任务/12路线/36知识/9实测是内容批次目标，不是整个站点的领域上限；36篇需覆盖通用基础和首批场景，不只制作创作术语。

新增模块未实现时标为待开发，不把文档/原型完成当成业务上线。只在有实际数据后开展登录、付费、云端问答、预测或自动执行。
