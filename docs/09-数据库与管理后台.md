# 数据库与管理后台

## 当前实现

React SPA + Node.js Express + SQLite（Node.js 24 原生驱动）。数据库默认 backend/storage/mendao.sqlite，适用于当前单台 ECS、单个后端实例。首次启动导入已有真实资料；后续以数据库为准，重新构建不会重置内容。资讯历史从旧 news.json 首次导入，后续采集写入数据库。

后台地址 /admin，支持知识及实践教程、工具、场景、模型的新增、编辑、搜索、状态筛选、预览、发布、下架、删除未发布内容、历史恢复与数据库备份。草稿与已发布版本独立，发布前校验关联文章/工具/场景，冲突返回 409。恢复历史只恢复草稿，需要再次发布才影响前台。

内容发布后公共 API 与 sitemap 即时读取新版本，浏览器重新进入页面或切回窗口会刷新数据。旧源码与 data/catalog.json 保留为首次初始化种子，不再是线上数据源；catalog:sync 不会覆盖数据库。

## 登录与安全

本地第一次启动，随机初始密码写入 backend/storage/admin-initial-credentials.txt，权限 0600，用户名默认 admin。首次登录必须改密，之后初始密码文件自动删除。生产首次启动必须通过环境变量配置 ADMIN_PASSWORD（12–128 位）和 ADMIN_USERNAME；已有管理员不会被环境变量覆盖。

密码使用独立盐 scrypt 散列；会话随机令牌在数据库中存储散列，8 小时失效。Cookie 为 HttpOnly、SameSite=Strict，生产加 Secure；写操作校验 Origin，生产 SITE_URL 必须匹配实际 HTTPS 域名。登录有账号与 IP 限速。改密撤销全部会话。没有公开注册接口。

当前后台账号拥有全部内容管理权限，不含编辑/审核员分级、多因素认证、用户个人账号或图片上传。资讯由公开 RSS 自动采集；后台目前不提供资讯逐条编辑与采集源配置。此范围避免人工编辑破坏原始来源记录。

## 备份与恢复

在后台点击“下载数据库备份”，通过 SQLite 在线备份 API 生成一致性快照，下载完成清理临时文件。快照包含内容、资讯、账号和会话，务必保存在受控位置，不要放进公开静态目录或代码仓库。

恢复步骤：
1. 停止后端服务，保留当前数据库及 -wal/-shm 文件的完整备份。
2. 用下载的 .sqlite 快照替换 DATABASE_FILE 指向的数据库；移走旧的同名 -wal/-shm 文件，防止旧日志与恢复库混用。
3. 确保运行用户有读写权限，数据库文件权限设为 600。
4. 启动服务，检查健康接口、已发布文章、后台账号和资讯。恢复也会还原备份时的密码与未过期会话；必要时立即改密撤销会话。

生产使用 compose 的 news-data 持久卷，名称为兼容旧部署而保留。禁止 down -v，更新镜像不会清空数据。建议每天导出备份并保留多份异地副本；本次未配置云端自动备份任务。

若忘记密码：停止服务，备份数据库后在项目根目录执行 `npm run admin:reset`（非默认路径需设置 DATABASE_FILE，非默认账号需设置 ADMIN_USERNAME）重置，随机新密码写入同一初始凭据文件且撤销旧会话，或恢复已知账号的备份。不要删除整个数据库以重置密码。

## 验收与部署范围

数据库发布边界、引用保护、乐观锁、历史、链接校验、资讯读写，以及 HTTP 登录/来源校验/首次改密/会话撤销都有自动化测试。已在 ECS Docker 环境部署测试与生产，参见 deploy/ecs/README.md；原有本机验收记录保留。

本机验收结果：65 项单元测试、22 项桌面/手机浏览器测试、类型检查、lint 和生产构建通过。浏览器管理操作使用临时数据库，未污染网站数据库。
