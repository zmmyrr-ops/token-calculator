# 用户体系与论坛

2026-09-17。普通用户体系与管理员体系独立。注册填写账号、密码、昵称；头像可选，未设置时使用昵称首字头像。注册成功自动登录，个人账号页可修改昵称、头像和密码，支持退出登录。

## 入口与讨论功能

- `/register` 注册；`/login` 登录；`/account` 资料与密码。
- `/forum` 分类、关键词搜索、分页列表，每页 12 条。
- `/forum/new` 登录后发布讨论；`/forum/:id` 查看正文、回复，每页 20 条回复。
- 作者可以编辑、删除自己的可见帖子，删除自己的回复；编辑带 revision 检查，冲突提示刷新。
- `/community-rules` 社区规则。帖子和回复为纯文本，HTML 不执行，不支持附件或 Markdown 渲染。
- 管理后台顶部“社区管理”：分别管理帖子、回复和用户；可下架/恢复内容、禁用/恢复真实账号。用户主动删除的内容不能经恢复按钮重新展示。

用户账号为 4–32 位字母、数字或下划线，统一小写；昵称 1–24 字符；密码 12–128 字符。当前没有邮箱/短信校验、密码自助找回、私信、点赞或云端收藏同步，普通账号不能进入管理后台。

## 示例数据

首次初始化写入 **120 个示例账号、48 篇原创话题、96 条回复**。所有记录真实存在 SQLite 中，用户 ID、帖子 ID 和回复外键有效；120 个账号均参与话题或回复，不通过硬编码伪造显示人数。

- 用户：`demo=1`、`disabled=1`，账号前缀 `example_v2_`，不设置可登录密码；即使错误恢复 disabled，登录和会话查询仍拒绝 demo 账号。
- 帖子与回复：`demo=1`，界面显示示例标识。
- 时间：实际初始化时间，不回填虚构的历史发布时间。
- 内容：原创问题、方法和检查清单，覆盖综合、模型与提示词、游戏、3D、美术、视频和建议反馈；不是转载文章，也不冒充用户真实经历或评价。
- 不伪造浏览量、点赞量、在线人数或埋点访问。回复数量直接从数据库中可见回复统计。
- `meta.communitySeedV2` 确保重复启动不重复插入，也不会恢复管理员下架的示例内容。后续修改种子文件不会自动覆盖已初始化数据。

实现见 `backend/src/community-seed.ts`。示例账号和普通用户均可在管理员用户列表中查看。普通注册用户和其发布内容均为 demo=0。

## 数据库

新增编号 3 的幂等建表迁移，仅新增表和索引，不覆盖旧内容或管理员账号。入口 `initCommunity()`，由服务启动与管理员路由初始化调用。

- `community_users`：id、唯一 username、nickname、password（scrypt 盐与摘要）、avatar（可空 PNG BLOB）、demo、disabled、created_at、updated_at。
- `community_sessions`：token（SHA-256 摘要主键）、user_id 外键、expires。
- `forum_posts`：id、user_id 外键、title、body、category、created_at、updated_at、revision、demo、status。
- `forum_replies`：id、post_id/user_id 外键、body、created_at、demo、status。
- `community_limits`：key、attempts、expires，登录、注册与写入频率限制。
- 索引：帖子 status/created_at，回复 post_id/status/created_at，会话 expires。公开列表和回复使用 SQL 过滤、LIMIT/OFFSET 与 COUNT。

status 为 visible、hidden（管理员下架）、deleted（作者删除）。删除为软删除，数据库和备份可能保留。禁用账号撤销会话并禁止登录、发帖；原内容需要单独下架，不自动清空。

当前论坛没有自动数据清理/归档，也没有账号自助注销。使用现有 SQLite 备份机制，备份包含账号、头像、帖子和回复，必须妥善保管。新增表为兼容性扩展，旧代码忽略这些表；回滚应用不应删除论坛数据。

## API 与认证

对外 `/api/community`，测试 `/staging/api/community`：

- GET `/session`：当前用户，无登录返回 `{user:null}`。
- POST `/register`：username、nickname、password、可选 avatar。
- POST `/login`、`/logout`；PUT `/profile`；POST `/password`（oldPassword、password）。
- GET `/avatars/:id`：PNG 图片；路径 v 参数对应头像更新时间，缓存 10 分钟。
- GET `/posts?page=&q=&category=`；POST `/posts`（title、body、category）。
- GET `/posts/:id?page=`；PUT `/posts/:id`（帖子字段和 revision）；DELETE `/posts/:id`。
- POST `/posts/:id/replies`（body）；DELETE `/replies/:id`。

管理员鉴权后 `/api/admin/community/posts|replies|users?page=` 查看每页 20 条记录，POST `/api/admin/community/:kind/:id/status`，主体 `{enabled:boolean}` 控制状态。管理操作记录到 history，actor 为实际管理员名。

用户 Cookie：生产 `mendao_user`、测试 `mendao_staging_user`；路径分别 `/api/community`、`/staging/api/community`，HttpOnly、SameSite=Strict，生产 Secure，有效期 7 天。修改密码撤销该用户所有会话。管理员 Cookie、账号表和权限不复用。

所有写接口检查 Origin；生产只允许 SITE_URL，测试站的 origin 仍为 https://ruming.top。公开作者信息只显示昵称、头像、示例标记等，作者账号 username 返回空字符串，用户自己及管理员才可读取登录账号。

## 头像处理

浏览器选择 PNG/JPEG/WebP，源文件最大 5 MB；在本地裁剪为 128×128 PNG，去除原始元数据，发送 data URL。服务端只接受 PNG 签名、IHDR 与尺寸检查通过的图像，最大 512×512、256 KB；拒绝 SVG 和其他类型。

图片保存在数据库 BLOB，不创建用户可控文件路径；输出 image/png、nosniff 和禁止脚本的 CSP。服务端不解码或执行上传内容；前端上传转换失败会提示换图。恢复默认头像将 avatar 置空。

## 基础防滥用与边界

- 全局每小时最多 20 次注册尝试；全局每分钟最多 120 次登录尝试；每个账号 15 分钟最多 10 次登录尝试，登录成功清除账号限制。
- 每用户每分钟最多 1 篇新帖、每天最多 10 篇；每分钟最多 3 条回复、每天最多 100 条。
- 资料修改每小时最多 30 次，密码修改每小时最多 10 次。
- 以上为按首次操作计时的固定窗口，存数据库。全局限额当前适合小站，不等同于按 IP 的反机器人识别；需扩大注册规模时应结合验证码、审核和更完善限流调整。
- 目前为发布后人工管理，不包含自动内容审核服务、举报处理队列、实时通知或反垃圾模型。管理员应定期检查新内容。
- 输入内容和账号密码不进入匿名埋点；登录、注册、账号页停止埋点；论坛详情仅记录路由类型，不记录具体帖子 ID。
