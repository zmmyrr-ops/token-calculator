## 1. 产品定位与核心利益

产品工作名称：**词元计算器**。首页主张：**“提问前，先算用量，再选模型。”**

用户粘贴问题或文本，查看词元数量与计算依据，设定回答长度和预算，比较可用模型的 API 成本，并获得可解释的选择建议。目标是帮助用户减少不必要的模型开销和选择负担。

核心利益按优先级排序：

1. **看清用量**：区别字符数与词元数，知道计数针对哪一种编码、是否包含历史对话。
2. **提前做预算**：把输入、回答、推理的用量与费用分开，避免只看每百万 token 单价。
3. **减少选择成本**：根据任务、质量需求与预算给出首选和备选，解释取舍。
4. **不为计算再付费**：首版本地计数和规则建议不需要用户提供 API Key。
5. **放心处理文本**：首版不上传正文、不默认保存正文；用户能检查和清除本地数据。

不承诺“准确预测未来 token”“保证最优模型”“保证节省固定百分比”。结果对用户有价值的前提是说明依据和适用范围。

## 2. 目标用户与典型任务

### 2.1 首要用户

- 独立开发者：准备发起 API 请求，需要估计输入和输出成本，避免上下文溢出。
- 使用多个模型的个人用户：不知道任务需要多强的模型，愿意参考简明建议。
- 内容与运营人员：长文摘要、翻译、改写前比较成本和输出长度。

API 按量付费用户更容易直接获得经济收益。订阅用户主要获得选型辅助；本产品不计算其剩余额度，也不推断平台内部计费规则。

### 2.2 用户故事

- “我有一段中文提示词，希望立即知道它在不同分词器下有多少 token。”
- “我要把文章翻译为英文，希望把预计回答也纳入预算。”
- “我有代码问题，希望知道低推理是否足够，以及什么时候需要更强模型。”
- “我每月会运行同一类请求，希望知道在固定用量假设下的月度费用。”

代码场景首版仅覆盖单轮代码问答。读仓库、运行命令、反复测试的 Agent 会话不属于首版预算范围。

## 3. 范围与发布边界

### 3.1 P0：可公开上线的基础版本

- 纯文本输入、中文/英文/代码示例、基本字符统计。
- 本地分词器计数，未知映射明确降级为估算或不可计算。
- 多模型费用比较、原币报价、可选人民币参考换算。
- 回答 token 的预算情景与自定义值；推理 token 作为独立预算项。
- 任务类型、使用偏好、模型候选筛选及规则建议。
- TXT/Markdown 文件本地读取，结果复制与 JSON/CSV 导出。
- 模型来源与更新时间、计算方法说明、隐私页面。
- SSR 首屏、移动端、基础 SEO、ECS 可部署产物。

首发模型目录要求覆盖**截至发布核验日期，市面上公开可查、仍提供使用或获取途径的所有中高端大语言模型**，不再采用“三个提供方、至少 6 个模型”的小范围目标。目录广度是 P0 必须验收的要求，不能因分词器尚未适配就删除模型或自行缩小收录范围。至少 2 种编码完成离线计数验证只是计算内核的最低门槛，不代表其他模型都能精确计算。

### 3.1.1 全量模型目录的收录标准

- 范围包括通用对话、推理、代码、长上下文，以及具备文本输入/输出能力的多模态中高端模型；保留仍在提供服务的上一代中高端型号。
- “中高端”没有统一行业等级。收录依据为厂商公开定位、适用能力和公开评测证据的综合判断，不以价格贵、参数量大或名称包含 Pro 作为唯一标准。边界不明但相关的型号先收录并标注“等级待核验”，不因主观判断遗漏。
- 闭源 API、开源权重、网页/客户端专属、公开预览、需要申请的模型均可收录；分别标注访问方式与限制。已下线型号放入历史档案，不参与当前推荐。未经官方确认的传闻不建正式条目。
- 同时可收录经济档作为省钱备选，但经济档数量不能抵扣中高端覆盖要求。嵌入、重排、纯图像/视频生成等不属于本次文本计算器范围。
- 模型家族、具体版本、推理模式、提供渠道分别管理。一个模型的多个渠道或别名不能冒充多个独立模型提高覆盖数。

首轮必须逐家核查的厂商/家族包括但不限于：

- OpenAI 的 GPT、推理与 Codex 相关模型；Anthropic 的 Claude；Google 的 Gemini；Grok。
- DeepSeek、阿里通义千问 Qwen、月之暗面 Kimi、智谱 GLM、MiniMax、字节豆包/Seed。
- 百度文心 ERNIE、腾讯混元 Hunyuan、讯飞星火、商汤日日新 SenseNova、阶跃星辰 Step、零一万物 Yi、百川。
- Meta Llama、Mistral 的通用/推理/代码模型、Cohere Command、Amazon Nova、AI21 Jamba。
- Microsoft Phi、NVIDIA Nemotron、IBM Granite、LG EXAONE、Xiaomi MiMo 等家族中符合上述定位的型号。

以上是**核查入口清单，不是已经录入或验证完成的数据库，也不是封闭白名单**。开发时逐个取得官方目录、模型卡或发布记录；遇到其他符合条件的厂商和型号继续收录。具体版本号以当次核验为准，不能凭记忆推断“最新版本”。

### 3.1.2 收录与计算支持分开验收

每个模型分别展示四项状态：

1. 目录资料：已核验 / 待核验 / 历史。
2. 文本计数：指定编码精确 / 参考或估算 / 暂不支持。
3. 费用：可计算 / 仅部分预算 / 无公开价格或订阅专属。
4. 选型建议：已实测 / 规则建议 / 仅资料展示。

网页专属模型照常展示，但不能拿另一 API 型号的价格冒充其费用。开源权重免费不等于推理免费；无具体托管报价或自托管成本输入时不显示零费用。用户从目录选择未适配项时，保留资料和明确原因，不伪造数字。

### 3.1.3 覆盖验收与维护

维护带核验日期的逐型号台账：官方来源、是否收录、收录 ID、未收录理由、资料缺口。首发前逐家检查官方目录，并通过公开模型目录/发布信息交叉发现遗漏；发现的符合范围型号必须全部有记录，不能用固定型号数量代替覆盖检查。

发布验收记录必须包含核查厂商数、独立型号数、各功能支持数、访问受限型号和已知缺口。任何已知符合范围但未入目录的型号都视为覆盖未完成；字段未知可以明示，不能用“已全部支持”掩盖。

运营目标：每周完整复核；发现正式发布/下线信息后 2 个工作日内更新目录状态，价格沿用 7/30 天时效策略。这是待实现的维护流程，本次没有创建定时任务。前台展示“目录核验至 YYYY-MM-DD”，不宣传永远实时全覆盖。

### 3.2 P1：验证需求后升级

- 结构化多轮对话、系统提示、工具定义的计数。
- 用户主动触发的云端任务分析、官方输入计数校验。
- 基于实际使用数据校准的回答/推理消耗预测。
- 浏览器侧边栏、更多分词器和模型、模型价格维护后台。
- 用户授权导入 usage JSON，用于个人历史比较。

### 3.3 P2：有付费意愿后再做

- 账号同步、团队预算、收费套餐、企业 API、自动路由。
- PDF/Word/图片等多模态计数与批处理。

P0 不实现登录、充值、支付、模型回答生成、自动切换第三方网站模型、聊天记录云同步或实时网页抓价。优先验证工具是否有复用价值。

## 4. 页面与信息架构

### 4.1 首页 `/`：唯一主工作区

桌面端最大内容宽度约 1200px，顶部导航高度约 64px。主体为左侧输入（约 55%）和右侧结果（约 45%），下方是模型比较、方法说明和 FAQ。移动端依次为输入、简要结果、推荐、可展开对比。

从上到下：

1. 轻量导航：品牌、模型价格、计算原理、反馈入口。
2. H1“词元计算器”，副标题“查看输入用量，比较模型成本，获得选择建议”。不用大幅宣传区挤占工具。
3. 输入区：原生文本框，示例切换、导入文件、清空；显示字符数、UTF-8 字节数。
4. 主设置：任务类型（自动/改写/摘要/翻译/抽取/代码问答/推理/其他）、偏好（省钱/均衡/质量）、从完整目录搜索加入对比（单次最多 6 个，限制仅用于同屏比较，不限制模型库数量）。默认均衡。
5. 输出预算：简短/标准/详细/自定义；旁边直接说明“预算假设，可修改”。单独展开“推理预算”，不能把回答长度当作推理强度。
6. 主要结果：当前模型输入 token、回答预算、推理预算、总费用情景；每个数据有“精确编码/估算/预算假设”的标签。
7. 推荐：一个首选、至多两个备选，列出理由、约束、何时升级；规则版标签为“规则建议”。
8. 模型比较：模型/渠道、输入数、推理模式、费用范围、数据日期、选择按钮。手机端逐项展开，避免整页横向滚动。
9. 高级区：已有输入 token 的手动补充、缓存命中假设、单次/月度次数、自定义价格、参考汇率。手动补充只影响预算，不代表校验过历史上下文。
10. 导出与方法说明，页脚展示备案信息配置位、隐私、版本日期。

交互文案不把内部字段、实现框架或“P0”暴露给用户。

### 4.2 其他页面

- `/models`：完整模型与渠道目录，支持厂商、任务、等级、访问方式、计数支持、计费支持筛选和分页；搜索中英文名称/API ID/别名。显示价格单位、模式、时效、官方来源以及各项支持状态。未核验条目不进入默认推荐。
- `/models/[slug]`：独立模型说明、计数精度、支持范围、价格日期。仅为有实质资料的条目生成页面。
- `/how-it-works`：解释输入、可见回答、推理、缓存、聊天封装、API 与订阅的区别。
- `/privacy`：本地处理范围、导出内容、未来云端功能的单独授权规则。
- 404 与错误页：回到计算器并保留可恢复的用户输入。

不生成大量只有模型名不同的 SEO 空页面。

## 5. 视觉与交互规范

- 风格：清晰、轻量的专业工具，浅色为主，系统深色模式可作为后续增强。
- 主色建议蓝色；中性色用于内容，绿色只用于已核验状态，橙色用于估算提示。所有状态同时有文字，不能仅靠颜色。
- 字体：本地系统中文字体；计数结果使用等宽数字。正文 14～16px，主标题 24～32px，行高不小于 1.5。
- 使用 8px 间距体系、清晰的输入边界和焦点样式；所有表单均有可读标签。
- 优先突出“建议与费用”，详细 token 分解可展开。
- 输入后防抖计数；改变模型不清空内容。旧结果计算中须标为“更新中”，禁止旧值冒充最新值。
- 复制成功有短反馈；复制失败提供手动选择文本。清空可以恢复最近一次，页面离开后不保留撤销正文。
- 无 JavaScript 时 SSR 页面仍能看到介绍、模型信息和说明，并明确提示启用 JavaScript 使用本地计算。

## 6. 功能需求与验收标准

### R01 文本输入和导入

- 支持粘贴和 UTF-8 `.txt` / `.md`；文件只在浏览器读取，最多 1 MiB；不支持的格式说明原因。
- 不自动 trim、不自动改换行、不改变 Unicode 规范化形式；计数对应当前文本框实际值。
- HTML/Markdown 作为纯文本显示，不执行脚本或渲染用户 HTML。
- 空文本显示输入引导；只有空格的文本允许计数。超限不截断，提示缩小文本。
- 验收：中文、代码、emoji、空格、换行、恶意 HTML、超限文件均有确定行为；网络请求不包含正文。

### R02 词元计数与精度

- 精确标签只描述“当前文本在指定编码版本下的计算值”，不是模型实际账单保证。
- 若模型映射未核实，显示参考编码名称；不能自动复用任意 GPT 编码并称为该模型精确计数。
- 估算结果使用 `≈` 与依据；缺乏可靠估算依据时显示不可计算，不返回假精确整数。
- 切换模型时保持输入，重新选择对应分词器；编码相同时复用计算结果。
- 验收：固定 tokenizer 的参考样例逐项一致；未知模型、缺失词表、Worker 失败不会显示 0 token 作为成功结果。

### R03 回答与推理预算

- 简短/标准/详细首先是预算情景，不宣称预测值；允许用户输入 token 上下界。
- 有推理模式的模型单列其可用选项；不支持的档位禁止选择。
- 未知推理消耗允许“未计入”状态，并将总费用显示为“部分预算”，排除完整预算排名。
- 提示实际回答、推理及后续工具调用可能超出情景；预算上界不是平台执行上限。
- 验收：无推理模式、推理未知、上下界倒置、负数、上下文容量不足都有明确结果。

### R04 费用对比

- 输入、缓存命中输入、可见回答、计费推理分别展示；提供方将推理包含在输出中时避免重复收费。
- 价格区分币种、调用渠道、地区、版本、计费模式、长上下文阶梯；默认标准按量价和无缓存假设。
- 人民币换算明确标记“参考换算”及汇率日期；无汇率时不进行跨币种最低价排名。
- 单次费用很小时显示足够小数，不能四舍五入成“免费”。月费只是单次情景乘请求次数。
- 验收：技术文档列出的价格演算用例、阶梯边界、缺价和过期价均通过。

### R05 模型选择建议

- 根据任务类型、偏好、语言、输入规模、输出需求和候选可用模式进行过滤、排序。
- 每个建议解释至少一个适配理由和一个代价；显示“规则建议”，不显示未经校准的成功率。
- 无足够证据时给出候选及“请自行比较”的说明，不强行宣布最优。
- 自定义价格不进入公开推荐；可在用户本次私人情景里排序并明确标识。
- 验收：简单改写不无理由默认最高档；容量不够/价格失效/不支持模式的候选不被推荐为首选。

### R06 来源与数据时效

- 每条价格、能力、tokenizer 映射独立记录来源和核验日期。
- 价格超过 7 天未复核提示，超过 30 天标为失效并退出默认费用排名；阈值是本产品维护策略。
- 显示模型是 API 条目，而非网页订阅模式。不得将 ChatGPT 显示名直接视为 API ID。
- 验收：用户能从结果访问具体来源；模拟过期数据后 UI 和推荐同步降级。

### R07 复制、导出与本地偏好

- 复制结果、下载 JSON/CSV；默认导出不含用户原文，用户明确勾选才包含。
- 导出包括参数假设、结果精度、模型/规则/价格版本、时间和币种。
- 默认只保存非敏感偏好，例如候选模型、币种、回答预算。正文仅内存保留，不写 URL、LocalStorage 或日志。
- 验收：刷新清除正文但保留偏好；禁用存储仍能使用；导出的版本能重现计算口径。

### R08 SSR 与 SEO

- 首页和模型页采用服务端渲染；HTML 中已有标题、工具标签、真实模型信息和方法说明。
- 不以空 div 等待浏览器加载全站，不能把全站 `ssr:false` 或静态导出当作 SSR 交付。
- canonical、站点地图、robots、Open Graph、语义化标题齐备；结构化数据与可见内容一致，不编造评分。
- 验收：关闭 JavaScript 或检查 HTTP HTML 仍可读核心公共信息；私人输入不出现在 SSR HTML 或分享 URL。

### R09 隐私与可用性

- 不接第三方会话回放，不收集输入正文、文件名、剪贴板、API Key。
- P0 网络用途限公共页面与静态资源；未来云端分析为单独按钮且先说明发送内容。
- 支持 375px 宽手机和桌面，键盘完整操作、焦点可见、结果状态可被辅助技术感知。
- 验收：XSS 和 CSV 公式注入被阻止；无远程字体或第三方脚本影响国内首屏。

### R10 性能与故障

- 目标而非已测结果：移动端 p75 LCP ≤ 2.5 秒、CLS ≤ 0.1、INP ≤ 200ms。
- 约 1 万字符、词表已加载情况下，输入结束后 500ms 内更新计数；1 MiB 文本在约定参考桌面设备上目标 3 秒内完成且可取消。
- 模型词表按需加载；失败可重试、换编码或显示估算。不能静默上传正文作为降级。
- 验收：发布前记录设备、浏览器、网络条件及测量结果，不能用开发机热缓存结果冒充所有用户体验。

### R11 运营维护

- 模型目录通过受校验的数据文件维护，首版不建后台。
- 支持反馈邮箱配置；正文不预填到反馈链接。
- 备案号、站名、正式域名、隐私联系方式由发布配置提供，不能用假值上线。
- 验收：模型更新可回滚；生产页无示例备案号、测试价格或损坏来源。

### R12 上线与阶段评估

- 首版完成关键路径测试、本地正文不外传检查、SSR 检查及 ECS 回滚演练。
- 早期目标是验证用户是否会第二次使用，以及推荐是否影响真实选择。
- 先邀请约 10 位 API 用户做自愿访谈，收集至少 30 次自报任务反馈；这是研究计划，不是现有数据。
- 不以页面访问次数证明推荐有价值。匿名行为统计若后续启用，单独定义口径和隐私说明；P0 不默认埋正文或持久用户标识。

## 7. 核心流程及异常状态

正常流程：进入首页 → 粘贴文本 → 选择或接受自动任务分类 → 本地计数 → 设置输出预算 → 查看规则建议与费用 → 复制/导出 → 去目标平台提问。

首次访问：说明“正文仅本地处理”，放置三种内置示例；不要要求登录。

多轮问题：提示粘贴的仅是本次文本；用户可以补充已知历史输入 token，但不能宣称覆盖平台内部提示。

疑似复杂 Agent 任务：展示“此处仅预算单轮，不含读取文件、工具结果与重试”，允许计数但不报整个任务准确费用。

模型不可用/无适配：保留用户输入、移除该候选；其他结果继续工作。

价格失效：展示最后记录及日期，关闭最低价推荐，而不是变成免费。

低于推荐证据门槛：输出“目前只能提供规则候选”，不展示伪造置信分数。

## 8. 商业化与阶段判断

P0 免费验证，避免一开始引入支付和账户成本。基本计数作为入口，持续价值来自可信的模型资料、预算和节省选择时间。

后续付费候选：批量预算、历史用量对账、团队模型策略、可验证的个性化推荐。是否收费由访谈与复用数据决定，本次不承诺收入或节省比例。
