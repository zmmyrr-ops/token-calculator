# AI 眼里的你：开发、使用与维护

2026-09-18。独立 PC Web 功能，支持窄屏浏览；不改变小程序入口。路由 `/ai-eyes`，后台 `/admin/ai-eyes`。原有 `/personas` 仍是说话风格 Skill。

## 用户怎么用

1. 打开「AI 眼里的你」，选择7天或30天，阅读授权范围，创建任务。
2. 复制专属指令，粘贴到一个新的本机 Codex 对话。需要 Python 3.10+、明确的当前线程 ID、可读的本机 Codex JSONL 历史。不适用没有本地历史的普通网页聊天。
3. 由该对话当前模型阅读清洗样本、选择固定16型，提交极小结果。网站不调用另一个模型，不上传聊天样本。当前 Codex 消耗仍计入用户额度。
4. 原页面自动显示报告；跨浏览器可使用领取链接。领取有效24小时，提交有效30分钟；完成结果保存30天。
5. 阅读完整原文；可自选另一型，系统推荐保持不变。昵称1–12个可见字符。
6. 可私密生成封面、完整长图、多页 PNG 或 ZIP。长图超出8192像素安全预算时改用完整多页，不裁剪正文。
7. 需要分享时先预览，再确认公开；公开页只含昵称、选择类型、固定原文。撤销或删除立即使链接失效，无法收回他人已下载的文件。

专属指令包含短期凭证，不要转发到公共讨论。页面刷新后不重新显示提交凭证；原浏览器仍可查看任务。领取地址使用 URL fragment，GET 不领取，确认按钮 POST 后清除 fragment。失去 Cookie 且领取过期后无账号恢复能力。

## 实际架构

React 懒加载模块 + Express API + 现有 SQLite。客户端 Canvas 使用同源 Noto Sans SC 字体和16张专属人物插画，串行生成 PNG，fflate 打包 ZIP。无需为每个访客在 ECS 启动浏览器，也无需站点模型密钥。公开分享由后端给 SPA 壳补充受控正文和社交元信息；并非将整站改回 SSR。

`data/ai-eyes/original.md` 保留原稿，`catalog.json` 保存受控段落及加粗，版本 `user-original-1`，SHA-256 `21360436a855a18cfa649df61623fa273a98c4683649e50e7532ecfd8aceeaa9`。同一版本禁止变更哈希。当前不提供后台原文编辑器；后续内容升级必须同时保留旧版本的前端渲染兼容性、执行包及图片，不可直接覆盖现有版本。

执行包 `/ai-eyes-tool/v4/`：说明、原文目录、JSON Schema、Python采样/验证/提交脚本、文件哈希清单和 ZIP。`npm run eyes:bundle` 重建清单；页面复制时附清单哈希。它用于完整性校验，不是独立信任签名。脚本需先审阅再执行，无远程脚本管道。

历史适配：本版为已知 JSONL 格式的只读兼容路径，尚未集成 App Server。只读 sessions / archived_sessions，排除当前任务、子代理、测试标记及无时间事件；按消息时间限制范围、会话及字数，清除明显代码/引用/路径/联系方式并去重。模型必须二次剔除引用、禁止执行样本指令；规则无法绝对识别自然语言来源。不得宣称覆盖所有 Codex 客户端。临时样本进入当前模型上下文，清理文件不会删除该平台会话。

## 数据库与接口

所有表使用 `ai_eyes_` 前缀，现有用户账号不受影响。

- `versions`：版本、原稿哈希、完整受控内容。
- `runs`：任务、owner/submit/claim 摘要、期限、固定范围、状态、结果、自选及分享引用。
- `grants`：领取后浏览器访问授权。
- `shares`：公开快照；更新自选不会静默修改已有快照，重新公开会撤销旧分享。
- `feedback`：每任务一次可更新的趣味/认领/阅读反馈。
- `limits`：短期限流摘要，不保存原始 IP。
- `settings`：是否允许新任务。
- `events`：日粒度操作次数，无昵称、结果说明、令牌或任务路径。
- `audit`：总开关与管理员撤销分享记录，90天保留。

API 基础路径 `/api/v1/ai-eyes`：`GET catalog[/version]`、`GET config`、`POST runs`、`GET runs/:id`、`GET runs/:id/execution`、`POST runs/:id/{progress,result,failure,cancel,selection,share,feedback}`、`POST claims/redeem`、`GET shares/:id`、`DELETE runs/:id[/share]`、`POST events`。后台复用已有登录权限，`/api/admin/ai-eyes` 提供概况、settings 修改、shares 撤销。

浏览器写请求检查 Origin；提交只接受 Bearer 短期凭证。run_id 不等于权限。提交正文16KB、严格字段白名单；同一结果幂等，不同结果冲突，终态不能再提交。Cookie HttpOnly / SameSite Strict，生产 Secure；staging 和 production 分离。每匿名会话每小时6任务，来源地址每小时30任务。当前应用未信任任意 X-Forwarded-For，代理后此限流可能按网关聚合；如需扩大访问量，应先部署可信代理地址传递链再调整，不能直接信任客户端提供的头。

## 备份、删除、发布

任务清理每小时运行，API访问也触发到期检查。在线结果完成后30天删除；取消/失败从创建起30天。备份沿用14天策略。

主动删除/分享撤销先写数据库同目录 `ai-eyes-deletions.jsonl`（0600），启动时重放并清理45天以前记录。恢复旧数据库时必须保留**最新**删除日志；只恢复 sqlite，不能用旧日志覆盖最新日志。服务启动重放后再接受流量。若整盘灾难导致最新日志也丢失，必须先禁止公开服务并核对撤销状态，不承诺可恢复此前所有删除记录。

发布沿用主分支 CI：check → build → 浏览器测试 → 两个容器构建 → staging → 精确 SHA 生产推广。新表由启动时幂等创建，发布前原有流程备份数据库。代码回滚保持 storage 目录，不手动删除新表/删除日志。开关关闭只停止新任务，已有任务仍可完成与删除。

## 验证与未覆盖边界

- 单元测试：原稿哈希/16型全文、严格输入、提交/访问凭证隔离、阶段顺序、幂等、终态、领取重试、撤销、到期清理、删除日志重放、采样夹具。
- 浏览器测试：桌面/移动 Chrome，任务→测试回调→完整报告→PNG→分享→撤销；测试数据仅隔离测试数据库。
- 批量视觉脚本：启动 Vite3017 后 `node scripts/verify-ai-eyes-export.mjs`。重生成16张无个人资料社交封面、每型所有分页到 `/tmp`；断言每原文块字符区间连续完整、页面不超高。已生成51页全文，16张封面。
- 尚未在用户真实 Codex 历史上执行授权分析，不把测试回调当真实模型匹配验收。无权限、历史格式不支持应显式失败；后续应在用户主动创建的一次任务中验证目标客户端。
- 移动端为 Chromium 尺寸模拟，真实 iOS Safari / Android 系统保存与扫码仍需设备验收。浏览器不能证明用户最终已在系统相册保存，统计为生成/下载操作次数。
